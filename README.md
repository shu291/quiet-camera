# 🔇 しずかカメラ

**シャッター音が鳴らず、聴いている音楽も止めない**カメラ。
そして——**本当に止まらないか、その場で確かめられます。**

ミスノートの中で「カメラを開くと音楽が止まる」問題を追いかけるために、
カメラだけを切り出した単体アプリです。ふだん使いのカメラとしてもそのまま使えます。

---

## なぜ無音なのか

端末の「写真を撮る」機能（`AVCapturePhotoOutput` など）を**一切呼びません**。
カメラのプレビュー映像の1コマを `<canvas>` に写し取って画像にしています。

- シャッター音を鳴らす仕組みを通らない → **音量設定に関係なく無音**
- 音声トラックを取得しない（`audio: false`）
- `Audio` / `AudioContext` をコードのどこでも使っていない

「音を消している」のではなく、**そもそも音の出る道を通っていない**という作りです。

> 撮影が禁止されている場所や、人が写る撮影では相手の同意が必要です。ルールを守って使ってください。

## なぜ音楽が止まらないのか

iOS は「そのページが音をどう使うか」で端末の音の設定を切り替えます。
何も申告しないと自動判定になり、カメラを起こしたときに
**録音向け（play-and-record）や再生向け（playback）**に切り替わることがあります。
どちらも「他の音を止める」設定なので、聴いている音楽が止まります。

そこでこのカメラは、**カメラを使っているあいだだけ**
`navigator.audioSession.type = "ambient"`（＝他の音と混ざってよい）を申告します。
WebKit の中では、この指定が自動判定より**優先**されます。

```
// WebKit / MediaSessionManagerCocoa.mm ／ updateSessionState()
else if (captureCount || …)      category = PlayAndRecord;   // ← ここに落ちると音楽が止まる
…
if (sharedSession->categoryOverride() != None)
    category = sharedSession->categoryOverride();            // ← ページの指定が勝つ
```

- 申告は**カメラを起こす前**に行う（起こしたあとでは、切り替わった設定を追いかけることになる）
- カメラを手放すときに**元の種類へ戻す**
- 対応していないブラウザでは何も起きない（害もない）
- **保険**：申告のせいでカメラが起動できなかったら、取り下げて一度だけやり直す
  （写らないより、音楽が止まるほうがまだましなので）

## 🎵 音チェック

画面左上の **「🎵 音チェック」** から。ボタンの丸の色がそのまま状態です。

| 色 | 意味 |
|---|---|
| 🟢 緑 | 申告できている（いちばん良い状態） |
| ⚪️ 灰 | カメラが止まっている／申告していない |
| 🔴 赤 | この端末には申告の仕組みが無い |

### 確かめかた

1. ミュージックなどで**音楽を流す**
2. このアプリに戻って **「カメラを止める → 入れる」** を押す
3. **音楽が止まらなければ合格**

この操作が、ふだん「カメラを開いた瞬間」に起きていることと同じです。

### 宣言のあり／なしを比べる

スイッチひとつで、申告を**する／しない**を切り替えられます（切り替えるとカメラを入れ直します）。

- **切った状態で止まり、入れた状態で止まらない** → この申告が効いている
- **どちらでも止まる** → ブラウザ側の作りの問題。記録を残して報告する
- **どちらでも止まらない** → もともと問題なし

### 記録

カメラの入り切りと、音まわりの変化を**時刻つき**で残します。
音楽が止まった瞬間の行を見れば、何が引き金かが分かります。
**「この内容をコピーする」**で、端末の情報ごとまとめて持ち出せます。

## 使ってみる

カメラは **https:// か localhost** でしか動きません（ブラウザの決まり）。

```bash
cd /Users/so/quiet-camera
python3 -m http.server 8110
# → http://localhost:8110
```

### iPad に入れる

Safari で開く → 共有ボタン → **「ホーム画面に追加」**
アイコンから全画面で起動し、オフラインでも動きます。

> 音チェックは **Safari と Chrome の両方**で試す価値があります。
> iPad の Chrome は中身が Safari（WebKit）ですが、
> アプリ側の作りが違うため結果が変わることがあります。

## 機能

| | |
|---|---|
| 撮影 | 完全無音。フラッシュは画面が白く光る演出のみ |
| 縦横比 | フル / 4:3 / 3:4 / 16:9 / 9:16 / 1:1 |
| ズーム | ピンチ or スライダー（1.0〜6.0×） |
| セルフタイマー | 3秒 / 10秒（カウントダウンも無音） |
| 連写 | 3 / 5 / 10 枚 |
| グリッド線 | 三分割 |
| カメラ切替 | 背面 / 前面 |
| 保存形式 | JPEG（画質調整可）/ PNG |
| ギャラリー | アプリ内に保存、まとめて「写真」に保存 / 削除 |
| 🎵 音チェック | 音楽が止まらないかの確認・申告のON/OFF・時刻つきの記録 |

**プレビュー = 撮れる写真**：ズームや縦横比の切り出し範囲を画面表示と同じ計算で行っているので、
見えているとおりに撮れます。

## ホームに戻って、もっかい開いたとき

裏に回るあいだはカメラを**手放します**（プライバシー表示を消し、他アプリの音を邪魔しないため）。
戻ってきたら**自動でつなぎ直します**。

戻ってきた合図（`visibilitychange` / `pageshow` / `focus`）は端末によって来たり来なかったりするので、
**どれか一つでも効けばよい**ように広めに拾い、それでも取りこぼしたときのために
**映像が進んでいるかを1秒ごとに見張って**います。止まっていたら起こし直します。

- カメラを二重に起こすと iOS はどちらの映像も出さなくなるので、起動は**一列に並べて**行う
- 起き上がる前にシャッターを押されたら、**絵が届くまで待ってから**撮る（空振り・真っ黒を防ぐ）
- どうしても駄目なときは「カメラを起動」のボタンを出す（**黙って固まらない**）

> 画面に出ているかの判定に `offsetParent` を使ってはいけません。
> `position:fixed` の要素（このアプリの `<silent-camera>` がまさにそれ）は
> `offsetParent` が常に `null` なので、戻ってきても永久に復帰しなくなります。

### 確かめかた

```bash
npm i -g playwright && npx playwright install chromium   # 最初の一回だけ
node tools/test-resume.mjs
```

偽のカメラを積んだ Chromium で「起動 → 撮影 → ホームに戻る → 開き直す」を繰り返します。
